# 第一章→第二章 セーブ継承仕様

## 結論

第二章は、第一章の完全なゲーム状態を直接読み込まず、正式報告後の状態から生成した「継承データ」だけを採用します。

## 入力できるファイル

- 第一章の結末画面から書き出した `haimachi.chapter1.transfer` JSON
- 第一章の設定画面から書き出した通常の巡察記録JSON

第二章側は通常の第一章セーブを受け取った場合も、正式報告、結末、救出状況、証人保護、雨鐘修復、推理成立数、信頼値だけを抽出します。

## 第二章へ反映する項目

- プレイヤー名
- 第一章の結末IDと結末名
- 失踪原因・責任主体・公開方針
- エルド救出の有無
- 証人保護の有無
- 雨鐘修復の有無
- 街の安定度・市民信頼・噂圧
- NPC信頼値の一部
- 第二章の初期NPC信頼、噂圧、派閥姿勢、地区状態

## 反映しない項目

- 第一章の座標、戦闘中状態、UI状態
- 任意のGameStateパス書き換え
- 未登録証拠や未登録NPCの追加
- 第二章の正式状態の直接上書き

## 設計理由

章をまたぐセーブを完全互換にすると、第一章側の内部実装変更が第二章を壊します。したがって、第二章は第一章を「世界史として要約」し、ゲーム開始時の初期条件だけを変えます。MCP連携時も同じ方針で、外部AIは候補を出し、正式状態はゲームロジックが採用・拒否します。


## 1.1.0 追加仕様：派閥状態の継続利用

継承時に変化した派閥状態は、巡察記録画面に表示されるだけでなく、以後の世界計算にも入ります。

- `rumor_brokers` の影響力が高いと、黒雨説・エルド証言捏造説が伸びやすい
- `ledger_cartel` の影響力と圧力が高いと、名前債務化・二重門番地説が伸びやすい
- `citizen_network` の姿勢が良いと、一部の噂成長を抑える
- `audit_bureau` の圧力が高いと、封印・管轄分割系の噂が伸びやすい

検証用サンプルとして `examples/chapter1_true_map_transfer_sample.json` を同梱しています。実プレイでは第一章の結末画面または設定画面から作成したJSONを使ってください。
